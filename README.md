# GitZero

GitZero runs pull-request CI on a pool of Mac Minis while GitHub remains the source of truth for repositories and pull-request checks.

The repository contains two cooperating planes:

- `apps/control-plane`: a Cloudflare Worker and Durable Object that accepts GitHub App webhooks, coordinates agents over WebSockets, and publishes GitHub Checks.
- `crates/gitzero-agent`: a Rust daemon for each Mac Mini. It checks out the exact pull-request test merge commit and executes compatible jobs from the repository's existing GitHub Actions workflow files.

The project is intentionally independent of GitHub's hosted runner routing. Repositories onboarded to GitZero disable native GitHub Actions in repository settings, preventing duplicate hosted runs while keeping `.github/workflows/*.yml` unchanged.

Production setup is fail-closed and uses one validated command to upload the Worker configuration and required secrets atomically; see [GitHub App setup](docs/github-app.md).

## Current compatibility

GitZero executes `pull_request` workflows at the exact GitHub test merge SHA pinned during durable initialization.

The webhook admits all 21 current GitHub `pull_request` activity types and does not suppress draft pull requests. Workflow discovery preserves GitHub's default `opened`, `synchronize`, and `reopened` behavior unless a workflow declares `types:`; nondefault activities run only explicitly matching workflows. Because aggregate Check creation precedes agent-side workflow discovery, an admitted event with no matching workflow concludes the GitZero Check neutrally instead of creating no Check. Open and unmerged PR activity uses `refs/pull/<number>/merge`; a merged `closed` activity uses the exact merge commit with `refs/heads/<base>`, matching GitHub's event context.

The implemented surface includes:

- concurrently scheduled workflow files and macOS jobs, GitHub-compatible string/list/group `runs-on` selection with all self-hosted labels enforced, negotiated routing of deterministically resolvable macOS/self-hosted selectors to the least-loaded matching Mac, repository-scoped workflow/job concurrency groups with case-insensitive keys, conditional cancellation, single-pending replacement, and FIFO `queue: max`, `needs`, static and expression-driven matrices with `include`/`exclude`, `max-parallel`, and fail-fast cancellation, plus pull-request activity/base-branch/path filters, job outputs, conditions, defaults, and tolerated failures;
- the complete authenticated pull-request webhook through `github.event` / `GITHUB_EVENT_PATH`, standard actor/repository/run/workflow/job/action identity in `github.*` and `GITHUB_*`, repository, accessible organization, and deployment-branch-authorized job-environment configuration through `vars`, typed `matrix` plus `strategy` index/total/parallel/fail-fast contexts, and GitHub expression functions, including an exact repository-scoped, masked `github.token` / `secrets.GITHUB_TOKEN` derived from workflow/job read and write `permissions` with reusable-call and untrusted-PR downgrades, authoritative installation-token expiry and pre-expiry refresh at acquisition and top-level step boundaries, runtime `add-mask` and `stop-commands` processing, native `error`/`warning`/`notice` commands plus job-scoped single-line and looping multiline problem matchers published as PR Check annotations, workspace-scoped `hashFiles`, step outputs, protected environment files and last-added-first path files, secret-masked `GITHUB_STEP_SUMMARY` Markdown surfaced in the PR Check, and action-wide step/job `timeout-minutes` with process-tree termination;
- durable, deduplicated webhook acknowledgement before external GitHub API work, followed by leased and retried merge-snapshot/variable/Check initialization that cannot dispatch an incomplete job to a Mac; a missing merge SHA is resolved with a pull-request-read token, pending mergeability is retried, conflicts complete without execution, and changed head/base identity fails closed;
- administrator-managed organization, repository, and environment secrets for unchanged `secrets.NAME` expressions, encrypted with randomized AES-256-GCM before Durable Object storage; organization/repository values are snapshotted at queue time, environment values resolve only after the job's environment and deployment branch policy are authorized, precedence matches GitHub, reusable calls must explicitly inherit or map names at every boundary, and fork, Dependabot, manual, or unverifiable runs receive none;
- GitHub Deployment records and running/terminal deployment statuses for branch-policy-authorized workflow environments without reviewer, wait-timer, or custom protection gates, pinned to the same exact merge snapshot as execution; lifecycle intent is stored before external writes, alarm retries recover ambiguous creates and status updates without duplicates, successful environment URLs are published, and `environment.deployment: false` opts out while retaining environment variables;
- shell steps with GitHub's distinct file-based default `bash -e {0}` and explicit `bash --noprofile --norc -eo pipefail {0}` behavior, custom shell templates, local, public, or owner-shared private GitHub-hosted JavaScript actions, composite actions with expression-driven nested `continue-on-error` and live `github.action_status`, environment-file and still-supported legacy command action outputs/saved state, and LIFO post entrypoints;
- nested same-repository plus public or owner-shared private remote reusable workflow calls up to ten total workflow levels, including per-run ref pinning, typed `workflow_call` inputs and defaults, static and output-driven call matrices with `max-parallel`/fail-fast, internal job dependencies, workflow outputs, caller conditions, cycle detection, and direct-call `secrets: inherit` or named aliases for managed secrets and the built-in token;
- empty, isolated workspaces and fresh `RUNNER_TEMP` roots for every matrix/job instance; exact authenticated merge/head/base-snapshot `actions/checkout`, defaulting to the pinned merge commit, plus anonymous public, App-authorized same-owner private, explicit managed-secret HTTPS-token, or managed-secret SSH-key cross-repository checkout with per-run ref pinning, at the workspace root or a contained relative `path`, including ephemeral `set-safe-directory` global Git configuration, SSH known-host/strict/user controls, depth-matched forced submodule checkout with automatic GitHub SSH-to-HTTPS conversion when no SSH key is supplied, cone/non-cone sparse working trees, and partial-clone filters for large monorepos; unchanged `actions/cache` and setup-action cache clients through a repository/PR-scoped Mac-local cache service; unchanged current-run `actions/upload-artifact@v4+` and `actions/download-artifact@v4+` transfers through a bounded loopback artifact service; shared runner tool and remote-action object caches; and a per-Mac execution limit shared across concurrent PRs.

The compiler or executor fails visibly for behavior it cannot reproduce. Current explicit gaps include Docker actions and container/service jobs, OIDC and `write-all` `GITHUB_TOKEN` permissions, automatic import of GitHub-hosted secret values, retained/GitHub-hosted/cross-run artifacts and cluster-shared workflow caches, protected-environment reviewer/wait-timer/custom gates, and pre-dispatch routing for selectors that depend on runtime state such as `needs` outputs or dynamic matrices. Explicit read/write permission maps are honored for same-repository PRs; the Worker reconstructs the signed webhook and converts every requested write to read for fork or Dependabot PRs before minting a token. Managed secrets use a separate administrator-controlled encrypted store because GitHub Apps cannot retrieve GitHub secret plaintext; values enter only trusted same-repository, non-Dependabot webhook runs and are masked before expression rendering. Private cross-repository actions and reusable workflows follow GitHub's native sharing boundary: the caller and target must have the same user or organization owner, the App installation must include the target, and the target repository's Actions access setting must authorize that owner scope. The Worker checks that policy with an internal administration-read token, then returns a different contents-read token scoped only to the target; the agent masks it immediately and never exposes it as `github.token` or a workflow secret. GitHub's empty-string behavior for missing properties remains present, so unchanged fallback expressions remain valid. Same-repository checkout supports root or safe relative paths, safe aliases for the webhook-authenticated PR head and base snapshots, `ref`/`commit` outputs, repeat-clean behavior, the built-in token, anonymous access, or a token whose rendered value exactly matches a managed secret visible to that job, depth, tags, progress control, sparse checkout, partial-clone filters, LFS, synchronized and forced depth-matched submodules, and ephemeral persisted credentials while always verifying the selected exact SHA. Its default `set-safe-directory: true` behavior copies the inherited global Git configuration to a mode-0600 file under the job's temporary root, adds only the canonical checkout path, uses that configuration for checkout's complete nested Git process tree, and deletes it when the step ends; `false` creates no override and neither mode mutates the Mac user's configuration. Named head/base aliases create local branches tracking `origin` refs reset to the authenticated SHA, and a merged `closed` event does the same for its default base ref; raw commit and `refs/pull/*` inputs remain detached. Without an SSH key, submodule URLs beginning with `git@github.com:` are converted to HTTPS and share the selected checkout token; the conversion composes with bounded pre-existing inline Git configuration and follows `persist-credentials`. An exact managed-secret `ssh-key` instead selects the standard SSH remote for either same- or cross-repository checkout and supports bounded `ssh-known-hosts`, `ssh-strict`, and `ssh-user` inputs; arbitrary literals and transformed keys fail closed. The agent writes the key and known-host data to mode-0600 files under that job's fresh `RUNNER_TEMP`, exposes only their paths through `GIT_SSH_COMMAND` when `persist-credentials` is enabled, and deletes the files whenever the job exits. Cross-repository checkout validates `owner/repository` and ref inputs, attempts anonymous access without sending the source token, pins a moving ref once per PR run, and verifies the resolved commit after materialization. If anonymous access fails for a different repository under the caller owner, the Worker can mint a separate target-only `contents: read` token from the same App installation. An explicit exact managed-secret token is instead sent directly to the selected target, including a cross-owner private target; arbitrary literal or transformed custom credentials remain rejected, while an explicit empty token remains anonymous-only. SSH, managed-token, anonymous-checkout, and shared-source authorization and materialized trees have separate purpose namespaces; each purpose proves remote access before consuming a run-wide pinned ref created by another purpose. Workflow caches are immutable per key/version, support exact and ordered prefix restore matching, remain isolated to one repository and pull-request ref, and are best-effort: a run dispatched to another Mac starts cold. Current-run artifacts are immutable by default, support the official overwrite/delete flow, archived and direct-file transfer, digest verification, and exact name/ID lookup, but are transient to the assigned run and Mac; the action's GitHub `artifact-url` output has no backing GitHub artifact record. See [architecture.md](docs/architecture.md) for the exact boundary.

Cross-repository checkout also preserves GitHub's branch topology without giving up GitZero's deterministic ref pinning. An explicit branch or an omitted ref resolved through the remote's advertised default branch creates a local branch with its `origin` upstream fixed to the commit selected for that PR run, so unchanged later steps can use plain `git push`. The default branch name and commit are reused across repeated checkouts in the run even if the remote moves or changes its default; tags, full commit IDs, and other refs remain detached. A default cross-repository checkout reports its canonical `refs/heads/<branch>` output just like `actions/checkout`.

## Development

Requirements: Rust 1.96.1+, Node.js 24+, and npm 11+. Production agents also require Git and Node.js 24 on every Mac because JavaScript actions use the machine's Node runtime; sparse checkout requires Git 2.28 or newer.

```sh
npm install
npm test
npm run check
npm run test:e2e
```

`npm run test:e2e` is a macOS-only, account-free acceptance test. It starts the Worker and its SQLite Durable Object through local Wrangler, creates a temporary repository with exact pull-request head and merge refs, connects two real Rust agents and an observer WebSocket, and submits two overlapping `labeled` jobs to a workflow that explicitly selects that activity. The test requires both jobs to execute the fixture workflow successfully from the pinned merge snapshot on different agents, verifies the relayed lifecycle/log events and final summaries, and removes every process, repository, secret file, work root, and local Durable Object database when it exits. The fixture's production-shaped `github.com` URL is mapped to its temporary bare repository only inside the spawned test agents, so production repository validation is unchanged and the test does not contact GitHub or a Cloudflare account.

Run the local control plane with `npm run dev --workspace @gitzero/control-plane`. Run an agent with:

```sh
cargo run -p gitzero-agent -- \
  --control-plane ws://127.0.0.1:8787 \
  --workspace-id local \
  --agent-token "$GITZERO_AGENT_TOKEN"
```

`GITZERO_AGENT_TOKEN` is minted by the authenticated control-plane agent-token endpoint for one workspace and one agent ID. It is not the Worker's agent-token signing key.

Secrets and GitHub App setup are described in [github-app.md](docs/github-app.md).

Repository onboarding uses an administrator-authenticated two-step gate. The read-only readiness endpoint confirms a connected compatible Mac, verifies a successful GitZero Check back from GitHub for the exact PR execution merge SHA, and reads the repository's native Actions state. An operator can then submit those exact evidence identifiers plus an explicit confirmation to the onboarding endpoint. The endpoint revalidates everything, disables native Actions with a separate repository-scoped token, and reads the setting back before reporting completion. Webhook delivery never invokes this administrative path.

The Worker exposes public `/healthz` liveness separately from authenticated `/readyz`, which locally validates the GitHub App credentials and secret hygiene without contacting GitHub.

For a release build and launchd installation on a Mac Mini, see [macos-agent.md](docs/macos-agent.md).
